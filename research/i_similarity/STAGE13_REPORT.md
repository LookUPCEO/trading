## 작업1 — 재시도/부분체결/타임아웃/거부 (OrderManager, 멱등성)
- **멱등성**: 주문마다 order_link_id. 재전송 전 link 로 상태조회 → 이미 체결/존재면 재전송 안 함 (중복 방지).
- **재시도**: 일시 오류(타임아웃/네트워크) 지수 백오프 최대 3회. 거부 코드(잔고/한도)는 재시도 X → 안전 중단.
- **부분체결**: place 후 cumExecQty 조회 → ledger 에 **실제 체결 수량** 기록 (요청 수량 가정 X).
- **타임아웃-실체결**: place 가 예외라도 실제 체결됐으면 멱등 조회가 인식 → 중복 주문 0.
- 리허설 (Mock 시나리오 ok/partial/transient/reject/timeout_filled): 전부 PASS. **실패를 성공으로 오인 = 포지션 미기록** (추적 깨짐 방지).

## 작업2 — 신호→주문 루프 통합
- 신호(i_shadow.Engine, bit-identical) → 안전장치(check_can_enter) → OrderManager.market(taker) → ledger(실체결 수량) → 4h deadline → reduce_only 청산.
- 가동 중 shadow 데몬 hot-patch X — 실행기 별도 프로세스, 같은 artifact.
- **실설계 발견 (one-way 넷팅)**: Bybit one-way 퍼프는 단일 순포지션만 — 30m/1h/4h 를 동시·다른 방향으로 독립 보유 불가 (넷팅됨). → **라이브 = 단일 4h thr0.70** (MAX_CONCURRENT=1). stage 7~10 이 이미 "단일 4h 가 운영점, 결합은 자본정규화 시 단일 미달" 결론냈으므로 정합. 청산=reduce_only 로 순포지션 0 복귀 확인.

## 작업3 — 리허설 (Mock Bybit, 실자금/실키 0)
- 전체 루프 결정적 검증 **12/12 PASS**: 정상체결, 부분체결(0.6×만 기록), 일시오류 후 재시도, 거부 시 미기록+재시도 안 함, 타임아웃-실체결 멱등, 4h deadline→reduce_only 청산(순포지션 0), 단일 포지션 상한, reconcile 정합, 정합 불일치→KILL.
- ⚠️ **실 Bybit testnet (실키 필요) = 사용자 액션** — Mock 은 응답을 결정적으로 시뮬(부분/타임아웃/거부 주입 가능)하므로 코드 경로는 실 testnet 1회보다 더 철저히 검증됨. 단 실 네트워크/체결지연/거래소 특이반응은 실 testnet 1회로 최종 확인 권장.
